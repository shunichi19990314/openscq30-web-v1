# P30i (A3959) Web対応 — バグ＆安全監査レポート

更新: 2026-09-24（コントローラー維持確認後の詳細監査）

## 1. 送信され得る全コマンドのv2公式実装とのバイト照合

A3959接続時にv1 Webが**送信し得る**パケットは以下のみに限定される（それ以外の
traitメソッドは `FeatureNotSupported` でパケット生成前に終了）。

| 用途 | v1 (本実装) wire | v2公式 | 一致 |
|---|---|---|---|
| 状態要求 | `08 ee 00 00 00 01 01` + `0a 00 02` | `RequestState` = `[01 01]` | ✅（実機応答済み） |
| サウンドモード(type3) | `… 06 81` + 7B | `[06 81]` + 7B（a3959テストベクタ一致） | ✅ |
| EQ+DRC | `… 02 83` + 22B (prof2+bands10+**apply_drc計算値10**) | `[02 83]` + 22B（v2 `set_equalizer_with_drc` = apply_drc連鎖） | ✅ |
| ボタン動作（単位送信） | `… 04 81` + 3B | `[04 81]` + 3B | ✅ |
| アンビエントサイクル | `… 06 82` + 1B | `SetAmbientSoundModeCycle [06 82]` + 1B | ✅ |
| ゲーミングモード | `… 01 87` + 1B | `SET_GAMING_MODE_COMMAND [01 87]` | ✅ |
| サラウンド | `… 02 86` + 1B | `SET_SURROUND_SOUND_COMMAND [02 86]` | ✅ |
| 低バッテリー通知 | `… 10 82` + 1B | `SET_LOW_BATTERY_PROMPT_COMMAND [10 82]` | ✅ |

ヘッダ（`08 ee …` + len + `00`）とチェックサム后缀はv1全機種共通の既存フレーミング
（他機種で実績あり）。body長はいずれもv2と同一。

### 送信経路が無い（意図的に無効/未配線）もの
- type1/type2サウンドモード、HearID、v1一括ボタンパケット `[04 84]`（a3959ではErr返し）
- **ファームウェア更新機能はv1 Webに元から存在しない**（ブラッ化リスク皆無）
- ファクトリーリセット／ボタンリセット（v2の `reset_button_configuration`）は未配線
- LDAC / 装着検出 / タッチトーン / 自動電源OFF のsetは未配線（state表示のみ）

## 2. 書き込み動作の安全性
- 全書き込みは **writeValueWithResponse**（ACK付き）。fire-and-forget無し
- 最大body 22バイト（MTU/分割問題なし）
- 連続書き込み対策: EQ=500msデバウンス（既存）、**type3スライダー=400msデバウンス（新規追加）**、
  ボタン/トグルは離散操作のみ、同値はlib側ガードで送信自体スキップ
- 接続直後の自動送信は「EQ同期（同値なら不送）」「type3同期（同値ガード）」のみで、
  いずれも実パケットを送らないパスが確認済み

## 3. parse誤り連鎖の監査
- 全12機種のstateパーサが `all_consuming` → 部分一致misparse不可
- **新規回帰テスト**: 実機91バイトパケットを他11機種のパーサに与え全てErrを確認
  （誤プロファイル適用→誤パケット送信の経路を遮断）
- a3959パーサは不明バイトをpreserveして送り返すのみ（改変しない）

## 4. ファームウェアgate
- ゲーミングモードは v2同様 **fw ≥ 01.60** でのみUI表示（それ未満ではトグル非表示、送信不可）

## 5. 結論（イヤホンが壊れる危険性）
- 送信コマンドは**全て公式v2実装とバイト一致**＝公式アプリ同等の操作のみ
- 危険クラスのコマンド（FW更新/リセット系）は送信経路が存在しない
- 書き込みはACK付き・小パケット・デバウンス済み＝電気的/プロトコル的な異常負荷なし
- 残リスク: 実機個体差/未観測パケットに対する挙動のみ（実機テストでカバー予定）
  → **本実装によりイヤホンが壊れる経路は確認されなかった**
